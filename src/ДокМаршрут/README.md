# ДокМаршрут — запуск

Конфигурация этапа 2: виды документов, маршрут согласования, журнал уведомлений, почта с PDF.

В этой папке лежит выгрузка в файлы (`Configuration.xml` и дерево метаданных). Для старта достаточно этой папки и платформы 1С. Скрипты сборки и готовые базы не нужны.

## Требования

- Учебная платформа **1С:Предприятие 8.5.1.1150** (проверяли на ней). Допустимо 8.3.27+.
- Управляемое приложение. На учебной 8.5.1 интерфейс платформы **8.5** (в конфигурации `InterfaceCompatibilityMode = Version8_5EnableTaxi` — это не классический «Такси» с жёлтой шапкой).
- Формат выгрузки **2.17**.

macOS, учебная: `/Applications/1cv8t.localized/8.5.1.1150/`.

## Что в репозитории

Нужно команде:

- эта папка (рядом с `Configuration.xml` — этот README);
- больше ничего для загрузки в Конфигуратор.

Не класть в git:

- файловые базы (`.1CD`, каталоги вроде `bases/`);
- `smtp.local`, пароли, ключи;
- локальные логи загрузки.

## 1. Пустая информационная база

1. Запустите стартер 1С.
2. **Добавить** → **Создание новой информационной базы** → **создание информационной базы без конфигурации**.
3. Имя, например `ДокМаршрут`.
4. Каталог базы — **новый пустой**. Не создавайте базу внутри папки с XML-выгрузкой.

## 2. Загрузка конфигурации (Конфигуратор)

1. Откройте базу в режиме **Конфигуратор** (не сразу Предприятие).
2. **Конфигурация → Открыть конфигурацию** (если дерево пустое).
3. **Конфигурация → Загрузить конфигурацию из файлов…**
4. Укажите **эту** папку — ту, где лежит `Configuration.xml`.
5. Не путайте с пунктом «Загрузить конфигурацию **из файла**» — это для `.cf`, не для этой выгрузки.
6. **Конфигурация → Обновить конфигурацию базы данных** (**F7**) → принять изменения.

В дереве конфигурации должно быть имя **ДокМаршрут**, подсистемы **Виды документов**, **Документы**, **Сотрудники**, **Уведомления**, **Сервис**.

### CLI (macOS, учебная), по желанию

```bash
/Applications/1cv8t.localized/8.5.1.1150/1cv8t.app/Contents/MacOS/1cv8t \
  DESIGNER /F"<путь_к_пустой_базе>" \
  /LoadConfigFromFiles "<путь_к_этой_папке>" \
  /UpdateDBCfg /Out load.log /DisableStartupDialogs
```

В `load.log` должны быть строки об успешном завершении / обновлении конфигурации. Слова `ошибка` / `исключение` / `XDTO` — стоп, разбирать лог.

## 3. Первый запуск (1С:Предприятие)

1. Стартер → та же база → **1С:Предприятие**.
2. В метаданных одна роль: **ПолныеПрава**. Кто «автор», «согласующий» и т.д. — через справочник **Сотрудники** и реквизит **ИмяПользователяИБ** (логин пользователя информационной базы).
3. Подсистема **Сервис** → обработка **Загрузка демо-данных** (сотрудники, виды с ≥2 этапами, документы).
4. **Сервис** → **Настройки почты**: SMTP, порт, SSL, логин; пароль только в форме, в выгрузку не зашит.
5. Сценарий: вид документа → документ СЭД → согласование по этапам → журнал уведомлений.
6. **Сервис** → **Проверки P0** — самотесты шаблона и метаданных.

### Ключ GigaChat (консультант)

1. Скопируйте `.env.example` из этой папки в **каталог файловой базы** (рядом с `1Cv8.1CD`) как файл `.env`.
2. Впишите свой Authorization Key: `GIGACHAT_AUTHORIZATION_KEY=...` (кабинет developers.sber.ru).
3. При первом вопросе консультанту ключ подставится в константу `КлючAPIИИ`, если она ещё пустая.

Файл `.env` в git не кладите. SMTP и пароль почты задаются только в форме **Настройки почты**, не в `.env`.

Пример SMTP: `smtp.mail.ru` или `smtp.yandex.ru`, порт **465**, SSL включён, логин — полный адрес ящика, пароль — пароль приложения.

## Типичные ошибки

| Симптом | Что проверить |
| --- | --- |
| Белый / пустой интерфейс | Выгрузка не загружена или не сделан **F7** |
| Зависание при загрузке | База лежит внутри папки XML; сделайте отдельный каталог базы |
| Диалог просит один `.cf` | Выбран пункт «из файла», нужен «из **файлов**» |
| «Мои задачи» пусто / предупреждение | У текущего пользователя в **Сотрудники** не заполнен **ИмяПользователяИБ** |
| Почта падает, документ жив | Смотрите журнал уведомлений; пароль/SSL в **Настройки почты** |

## Короткий чеклист перед демо

1. Пустая база → загрузка из файлов → F7.
2. Демо-данные.
3. У сотрудников заполнены **ИмяПользователяИБ** под логины сеанса.
4. Почта настроена (или осознанно без SMTP — тогда смотреть журнал сбоев).
5. Один полный круг согласования + **Проверки P0**.
